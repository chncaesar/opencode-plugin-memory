向记忆系统提候选之前，先问一句向前看的话：**这条规则做完之后，工件会不会自己说出来？**

用未来式问，是因为用"现在看得见吗"判断会在两端各错一次：已完成的需求被重复记录；尚未完成的需求因为"现在看不见"而被奖励存入，等它落地就变成重复。

- 已经落地（屏幕、代码、设计稿已经是这样）→ 工件会说出来 → 不存。例：release-agent 把「每个任务状态只给一个主操作按钮」做成界面后仍存了记忆，而该规则本属 DESIGN.md。
- 还没落地（用户刚提的需求）→ 仍问同一句：它做完之后工件会不会说出来？会 → 它属于任务清单或设计稿。**「还没做完」不是存进记忆的理由，只说明它现在没有家。**
- 只有「做完也不会写在任何地方」的才进记忆：字段的真实语义（库里只有字段名）、历史坑与为什么不能这么干（旧部署方式会静默上线未提交的改动）、否定性边界（设计稿里没写的功能不许加按钮）。

记忆不是任务清单。确实要存一条待落地的规则（且没有其他载体）时，它的寿命就是这一次任务，落地时应以 implemented 为理由退休，否则临时记忆会悄悄固化成重复。
